## 1. 范围

| 做 | 不做（本档） |
|---|---|
| 列出域内全部 GPO | 新建 / 删除 GPO |
| 看某个 OU（或域）**套了哪些 GPO**、顺序、是否启用/强制 | 链接 / 解除链接 |

## 2. 关键更正：需求文档 §2.2 有一行是错的

需求文档 §2.2 的能力矩阵里写着：

> 看某 GPO 链在哪些 OU ✅ 靠 `IGPMGPO.GetGPOLinks()`

**`IGPMGPO` 根本没有这个方法。** 类型库实测（`tools/probe_gpo_typelib.py`）
`IGPMGPO` 的全部 36 项里，`GetGPOLinks` **不存在**：

```
IGPMGPO（36 项）
    DisplayName / Path / ID / DomainName / CreationTime / ModificationTime
    UserDSVersionNumber / ComputerDSVersionNumber
    UserSysvolVersionNumber / ComputerSysvolVersionNumber      ← 10 个属性
    GetWMIFilter / SetWMIFilter / SetUserEnabled / SetComputerEnabled
    IsUserEnabled / IsComputerEnabled / GetSecurityInfo / SetSecurityInfo
    Delete / Backup / Import / GenerateReport / GenerateReportToFile / CopyTo
    SetSecurityDescriptor / GetSecurityDescriptor
    IsACLConsistent / MakeACLConsistent                        ← 18 个方法
```

链接**只长在 SOM 那一侧**：

```
IGPMSOM（17 项）
    GPOInheritanceBlocked / Name / Path / Type                   ← 属性
    CreateGPOLink / GetGPOLinks / GetInheritedGPOLinks
    GetSecurityInfo / SetSecurityInfo                            ← 方法
```

⇒ **反查方向必须倒过来**：不是"问 GPO 它链在哪"，而是"**问 SOM 它链了什么**"。
两条正路：

| 目的 | 调用 |
|---|---|
| 某 GPO 链在哪些 SOM | `SearchSOMs(criteria.Add(SearchPropertySOMLinks, SearchOpContains, gpo))` |
| 某 SOM 链了哪些 GPO | `GetSOM(path, somOU).GetGPOLinks()`（含继承用 `GetInheritedGPOLinks()`） |

⚠️ 这行错误的教训值一条红线：**能力矩阵是"想当然"写出来的**，而它会被后面的人
当成事实去实现。凡"某某方法能做某某事"，**要么有类型库/官方文档原文，要么进判决实验**。

## 3. 常量名：文档、类型库、COM 对象是三个不同的东西

这是本次调研最实际的收获。同一个"GPO 显示名"的搜索属性，三种写法里**只有一种能用**：

| 来源 | 写法 | 实测 |
|---|---|---|
| 老 MSDN 方法页的 Remarks 表 | `gpoDisplayName` | ❌ `AttributeError` |
| 类型库（`gpmgmt.dll` 的枚举成员） | `GPODisplayName` | ❌ `AttributeError` |
| **COM 常量对象（`GetConstants()`）** | **`SearchPropertyGPODisplayName`** | ✅ `= 2` |

`tools/probe_gpo_typelib.py` 的"候选常量实测"段第一次跑就抓出 **10 个 MISSING**
（`GPODisplayName`/`GPOID`/`somLinks`/`GPODomain`/`opEquals`/`repXML`…）。
**如果照文档抄进代码，就是 10 处 `AttributeError`；如果给它们加了 `try/except` 兜底，
就变成 10 处静默失效** —— 后者是最难查的一类缺陷。

**已确认可用的名字（实现里只许用这些）**：

| 语义 | 真实名字 | 值 |
|---|---|---|
| SOM 类型：站点 / 域 / OU | `somSite` / `somDomain` / `somOU` | 0 / 1 / 2 |
| 搜索属性：显示名 | `SearchPropertyGPODisplayName` | 2 |
| 搜索属性：GPO ID | `SearchPropertyGPOID` | 4 |
| 搜索属性：链路（反查 SOM） | `SearchPropertySOMLinks` | 7 |
| 搜索属性：GPO 所在域 | `SearchPropertyGPODomain` | 8 |
| 搜索操作：等于 / 含 / 不含 / 不等于 | `SearchOpEquals` / `SearchOpContains` / `SearchOpNotContains` / `SearchOpNotEquals` | 0 / 1 / 2 / 3 |
| 报告类型：XML / HTML | `ReportXML` / `ReportHTML` | 0 / 1 |
| `GetDomain` 的 flags | `UsePDC` / `UseAnyDC` / `DoNotUseW2KDC` | — |
| 权限（安全筛选展示） | `permGPORead` / `permGPOApply` / `permGPOEdit` / `permSOMLink` / `permSOMGPOCreate` | 65792 / 65536 / 65793 / 1835008 / 1049600 |

`tools/probe_gpo_typelib.py` 是这条红线的**执行装置**：它不碰 AD、不碰 SYSVOL，
任何机器上都能跑；实现里用到的常量，必须能在它那里查到。

## 4. 接口设计

新模块 `gpo_backend.py`，与 `ad_client`(LDAP) / `password_backend`(身份) 平级。**零 UI**。

```python
# ---------- 前置 ----------
def engine_status() -> tuple[bool, str]
    """GPMC 引擎在不在。返回 (可用, 说明)。

    ⚠️ 不可用时**必须**说成「本机未安装 RSAT 组策略管理工具」= **部署前置条件**，
    不许包装成「连接失败」—— 使用者会去查网络，而问题在没装东西。
    """

# ---------- 会话 ----------
@contextmanager
def open_session(domain: str, dc: str = "", *, user="", password=""):
    """打开 GPMDomain。退出时放手 COM 对象。

    * `domain` 来自 `ad_client.domain`（RootDSE 反查）—— **禁硬编码**；
    * `dc` 为空 ⇒ flags 用 `UseAnyDC`；给了 IP ⇒ 直接指定；
    * 给了 user/password ⇒ 外面再包一层 `password_backend.impersonate()`。
    """

# ---------- 只读查询（全部纯读） ----------
def list_gpos(domain, dc="", ...) -> list[GpoInfo]
def search_gpos(domain, dc="", text="", ...) -> list[GpoInfo]
def list_soms(domain, dc="", ...) -> list[SomInfo]
def links_of_som(domain, dc="", som_path="", inherited=False, ...) -> list[GpoLink]
def soms_linking_gpo(domain, dc="", gpo=None, ...) -> list[SomInfo]
def generate_report(domain, dc="", gpo=None, fmt="html", ...) -> str
```

数据类：`GpoInfo(guid, display_name, domain, path, created, modified,
user_enabled, computer_enabled)`、`SomInfo(path, name, kind, blocked)`、
`GpoLink(gpo_id, display_name, enabled, enforced, order, som_path)`。

### 4.1 每个界面动作 → 哪个调用

| 界面动作 | COM 调用 |
|---|---|
| 打开面板，列 GPO | `gpm.GetDomain(...)` → `GetConstants()` → `SearchGPOs(空 criteria)` → `GPOCollection` |
| 搜索框过滤 | `SearchGPOs(criteria.Add(SearchPropertyGPODisplayName, SearchOpContains, 关键词))` |
| 选中某 GPO，看它链在哪些 OU | `SearchSOMs(criteria.Add(SearchPropertySOMLinks, SearchOpContains, gpo对象))` |
| 选中某 OU，看它套了哪些 GPO | `GetSOM(ou, somOU).GetGPOLinks()` → `GPMLinksCollection` |
| 看设置摘要 | `GenerateReport(ReportXML 或 ReportHTML, None, None)` → 字符串 |
| 安全筛选 | `GetSecurityInfo()` → `GPMSecurityInfo`（`Item(i)` 有 `Trustee`/`Permission`） |

⚠️ **`SearchGPOs(空 criteria)` 是"全部"** —— `CreateSearchCriteria()` 之后一次 `Add`
都不调，就是不给条件。不许拿"遍历所有 OU"去凑列表（那是第二份实现）。

### 4.2 「空结果」不是「失败」

沿用 09-15 真域修过的口径：`SearchGPOs` 返回 0 项是**合法结果**（域里可能真没有 GPO），
返回 `None`/抛异常才是失败。两者在界面上必须长得不一样。

## 5. 身份通道：GPO 走的是哪一条路

这点很容易搞混，写死在这里：

| | 组策略（本项） |
|---|---|
| 传输 | **DCOM/RPC + LDAP**（135 + 动态端口 + 389） |
| 换凭据的手段 | `password_backend.impersonate()` = `LogonUser` + `ImpersonateLoggedOnUser` |
| 为什么 | GPMC 是 COM/RPC 调用，用的是**线程令牌** ⇒ 必须真的挂令牌 |
| 断连 | `finally` 里 `RevertToSelf` + 关令牌 |

**这条路不能换成「建一条网络连接带凭据」那种做法。** `WNetAddConnection2` 解决的是
**出站网络访问**的凭据问题，进程令牌不变；而 GPMC 吃的是 DCOM/RPC 的**线程令牌** ⇒
两者是不同的装置，**不能互换**。

**这条通道必须单独验。** `tools/probe_impersonate_unc.py` 那组判决实验证明的是
"SMB 那条路 `WNetAddConnection2` 真的用上了凭据"，**它没有证明、也不能证明
GPMC 这条路怎么走** —— 那是另一个实验。

### ⚠️ 未验证项（诚实记录，不许当成已成立）

`impersonate()` 用的是 `LOGON32_LOGON_NEW_CREDENTIALS(9)`。它的语义是
"**本机身份不变，出站网络访问用这份凭据**"。对 GPMC 的**出站 DCOM/RPC** 调用，
方向上应该有效 —— 但这是**推断，不是实测**（域不通）。

⇒ 因此验收脚本（`tools/acceptance_gpo.py`）里配一条**凭据反证**：
用**故意错误的口令**去调 GPMC，**如果照样成功**，说明凭据根本没起作用
（与「假凭据应当被拒」同一手法）。这条不通过，就不许对外说"能用域账号跑组策略"。

## 6. 红线（本档专属）

1. **只读**：对外函数里不许出现 `CreateGPO` / `CreateGPOLink` / `Delete` / `Backup` /
   `Import` / `CopyTo` / `Set*`。配 **AST 静态判据**（读函数体里的调用名），不靠人眼。
2. **常量名以类型库为准**：`getattr(constants, 名字)` 失败**必须原样抛出**。
   给常量读取加 `try/except` 兜底 = 把"拼错名字"变成"功能静默不生效"，禁止。
3. **引擎缺失 ≠ 连接失败**：报成「本机未安装 RSAT 组策略管理工具」+ 怎么装，
   不许报「连接域失败」。
4. **禁硬编码域**：`domain` 只能来自 `ad_client.domain`（RootDSE 反查）。
5. **零自造**：不解析 `registry.pol`、不解析 `GptTmpl.inf`、不自己拼 LDAP 查 GPO。
   设置摘要一律走 GPMC 的 `GenerateReport`。
6. **不碰 SYSVOL 的文件**：报告由 GPMC 产出，我们不读也不写 `\\域控\SYSVOL`。

### 9.3 为什么验收脚本**没有** `--execute`

根本没有这个开关** —— 一个不存在的开关没法被误用。

* `tests/test_acceptance_gpo.py` 钉住「解析器里不许出现写开关」「源码里不许
  出现 GPMC 写方法」（AST 读属性名，**不读文本** —— 本文件与脚本的说明文字里
  就写满了 `CreateGPO` / `--execute`）；
* 反证 **C107 / C108** 证明这两条判据真的会变红（各只红一条）。

（哪天组策略真加了写功能，再照 `acceptance_live.py` 的形态补
「默认只读 + `--execute` 才写 + 只打 `zz_wbtest_*` 临时对象 + `finally` 清理」。）

## 10. 交付后审计：「XML 摘要」这条路径**界面上够不到**（待拍板）

> 本节只追加。是**交付之后**回头逐条走"从界面出发能不能到达"时发现的。

### 10.1 事实（可复现）

| 位置 | 代码 | 后果 |
|---|---|---|
| `ui_browser._submit_gpo_report` | `fmt = "html"` ← **写死** | 界面发出的 `fmt` 永远是 `"html"` |
| `ui_panels.GpoPanel.report_requested` | `pyqtSignal(str)` —— **只带 GUID** | 面板没有携带格式的通道 |
| `ui_browser._submit_gpo_report` | `self.tasks.submit(..., self.client, guid, fmt)` | 透传的是上面那个常量 |

⇒ 从**界面**出发，`gpo_report(client, guid, fmt=…)` 的 `fmt` **永远等于 `"html"`**：

```
界面「看设置摘要」→ fmt="html" → gpo_report → gpo_backend.generate_report
                                                  └─ REPORT_XML 分支：够不到
```

### 10.2 为什么这值得记一笔（而不是"留着以后用"）

这是本项目红线里 **「跑得通」≠「跑得到」** 的又一例，而且形态更隐蔽：

* 它不是死代码 —— `generate_report(..., fmt=)` **有**调用点（`workers.gpo_report`）；
* 两条用例（`test_xml_report_passes_the_xml_constant` /
  `test_xml_report_is_shown_as_plain_text`）**是绿的**，看着像"XML 功能有覆盖"；
* 但它们绿着，却**描述不出一条使用者能走的路**。

⇒ 危险在于**下一个人会以为产品支持 XML 摘要**。
所以本轮先做了**零行为改动**的诚实化：那两条用例的 docstring 现在明确写着
"验的是后端参数，不是产品能力"，并指向本节。

### 10.3 待拍板（**两条路，我倾向 (a)**）

| 方案 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **(a) 删掉 XML 链路** | 移除 `REPORT_XML` / `GpoPanel.show_report` 的 xml 分支 / `NEEDED_CONSTANTS` 里的 `ReportXML` / 上述两条用例 | 改 5~6 处，`ReportXML` 常量从名单消失 | **倾向**：目前**没有任何使用者需要 XML**，也没有任何东西会去解析它 —— 属于「猜测性的能力」。红线写着「零调用点即死代码，删」|
