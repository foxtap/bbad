# 设计：安全策略（`GptTmpl.inf`）编辑

> 日期：2026-09-15　对应需求文档第 **5** 项
> 状态：**设计已定，尚未实现**。写操作风险高（微软 KB 原文：改错「may make your
> domain controllers inoperable」），按项目纪律**先设计、不擅自实现**。
> 前置判决实验：`tools/probe_gpttmpl_format.py`（E1~E8，**本机可跑，不碰 AD/SYSVOL/域**）

---

## 1. 范围

这是本工具里**第一个直接改「策略内容」的写操作**（前四项是 LDAP / COM / ACL）。
范围必须比前几档更窄，理由见 §3。

| 做（v1） | 只读展示（v1 不给改） | 不做 |
|---|---|---|
| `[System Access]` —— 账号策略：密码长度/复杂度/历史、锁定阈值/时长/计数器重置 | `[Privilege Rights]` —— 用户权限分配 | 新建 / 删除 GPO |
| `[Event Audit]` —— 审核策略 9 项 | `[Group Membership]` —— 受限组 | 改 `registry.pol`（管理模板，第 6 项） |
| `[Registry Values]` —— **白名单键**（不是全量） | `[File Security]` / `[Registry Keys]` | 改安全筛选 / 委派 |
| 只读：完整列出 `GptTmpl.inf` 全部段与键（原样） | `[Service General Setting]` | 编辑 `GPT.INI` / AD 属性以外的东西 |

**为什么这个切法不是"偷懒"**：需求文档 §2.3 写的是「工厂 IT 最常改的（密码长度/
复杂度/锁定阈值/账户锁定时间/审核策略）**全在第一层**」。而"第一层"里真正被点名
的那几项，恰好**全部**落在 `[System Access]` + `[Event Audit]`。
**也就是说：安全的那部分正好是够用的那部分** —— 不是妥协，是重合。

被划成只读的三段，各有**具体的**技术理由（不是"怕麻烦"）：

| 段 | 只读的理由 | 证据 |
|---|---|---|
| `[Privilege Rights]` | **全量替换语义**：`SeNetworkLogonRight = A,B` 的意思是「**只有** A、B 有这个权限」，不是「加上 A、B」。界面上让人"勾选增加几个人"，写下去却是全量 ⇒ 一旦解析漏认一种主体形态，**保存就等于删掉那几个人** | §4.3 实测：只认 `*SID` 会漏 **4/71** 个主体 |
| `[Group Membership]` | 同样是全量替换：`*S-1-5-32-545__Members = *S-1-5-11,*S-1-5-4` 是**重写整个成员列表**，写错 = 清空组 | 实物（`defltbase.inf`） |
| `[File Security]` / `[Registry Keys]` / `[Service General Setting]` | 值是 **SDDL 全量替换** —— 与 §1 里 ACL 那条红线同一个坑，而且更难审阅 | 实物 + 需求 §1 |

> ⚠️ 注意这三段**仍然要能读出来给使用者看**。「只读」不等于「隐藏」——
> 藏起来，使用者就以为工具不支持看这些设置。

## 2. 判决实验结论：需求文档 §2.3 那句「INI 读写」是**危险的简化**

需求文档 §2.3 对安全策略的可行性判断是：「✅ 纯文本 INF ⇒ **INI 读写**，
字段就是 `MinimumPasswordLength = 14` 这种」。

**格式那一半是对的，方法那一半是错的。** `tools/probe_gpttmpl_format.py`
在真实样本上给出相反的证据：

| 编号 | 实验 | 实测结论 |
|---|---|---|
| E1 | 样本来源 | 3 份：`secedit /export`（**操作系统自己生成**，17 358 字节）、`C:\Windows\inf\defltbase.inf`（Win 自带，29 572 字节）、KB324800 引文 |
| E2 | 编码 / 行尾 | 三份**全部** `utf-16-le` + BOM `FF FE` + CRLF |
| E2b | **BOM 是不是承重的** | **是**。同一内容去掉 BOM ⇒ 编码被判定成 `cp1252` ⇒ 段解析出 **0 个**，且**没有任何异常** |
| E3 | 段名/键名大小写 | **跨样本不一致**：段 `[Version]` vs `[version]`；键 `SeSystemTimePrivilege` vs `SeSystemtimePrivilege` |
| E4 | `[Privilege Rights]` 值形态 | **4 种**：`*SID` / `&相对SID` / **裸账号** / **`域\账号`** |
| E5 | `[Registry Values]` 类型码 | 出现 **`8`**（带 `Remove:` 前缀），而它**不在微软自己写在该段注释里的类型表**（1/2/3/4/7）里 |
| E6 | 定点替换的字节保真 | **做得到**：改 1 个值只动 3 字节（`b'0'`→`b'1\x004'`），BOM/行尾/注释/其它段 100% 不变 |
| E7 | 版本号递增 | 32 位 = 高 16 用户 / 低 16 计算机；**KB324800 教的「末尾加 0」会破坏语义** |
| E8 | 写进 SYSVOL 之后 | 还必须让 AD 的 `gPCMachineExtensionNames` 含安全 CSE GUID，否则文件被**完全忽略** |

⇒ **六个必须遵守的设计约束**（下面各节展开）：

1. **不许「解析→重建」** —— 必须**定点行内替换 + 字节保真**（E6）
2. **匹配全部大小写不敏感**（E3）
3. **主体形态要么全认、要么拒写**（E4）
4. **不认识的类型码：保留原样，不许删**（E5）
5. **版本号自己按位算，不照 KB 抄**（E7）
6. **AD 属性不满足前提就拒绝写**，不许「假成功」（E8）

## 3. 为什么不许「解析→重建」（本设计的第一条铁律）

最自然、也最危险的实现是：`configparser` 读进来 → 改一个键 → `write()` 写回去。

**它会毁掉四样东西**，而且**四样都是人和机器都要读的**：

| 被毁掉的东西 | 例子（全部来自实测样本） | 后果 |
|---|---|---|
| 注释 | `defltbase.inf` 292 行里有 **105 行**注释（`grep -cE '^\s*;'`），含**类型码对照表**和 SID 对照表 | 下一个维护者看不懂这份策略 |
| 值格式 | 同一逻辑值两种写法：`LegalNoticeText=7,""`（自带模板）vs `7,`（OS 导出） | 全量重写会把差异抹平 ⇒ diff 无法审阅 |
| 段顺序 | `[Version]` 在 `defltbase.inf` 里排第 2，在另一份样本里排最后 | 重排 ⇒ 整文件 diff |
| 大小写 | `[version]` / `[Version]` | 同上 |

**为什么这件事这么重要**：改策略内容是一份**高危写操作**，它唯一的安全阀是
**人能看懂 diff**。一份 292 行的文件，如果改动被淹没在 292 行"格式规范化"里，
等于没有安全阀。

⇒ 采用**行定位的字节级替换**（E6 已证明可行）：
只在原始文本里找到**那一行**，替换 `=` 之后的值，其余一切原样。

## 4. 格式真相（实测，不是抄文档）

### 4.1 段清单

| 来源 | 段 |
|---|---|
| `secedit /export`（6） | `[Unicode]` `[System Access]` `[Event Audit]` `[Registry Values]` `[Privilege Rights]` `[Version]` |
| `defltbase.inf`（13） | 上面 6 个中除 `[Event Audit]`/`[Unicode]` 外，加 `[Profile Description]` `[System Log]` `[Security Log]` `[Application Log]` `[Group Membership]` `[Service General Setting]` `[Registry Keys]` `[File Security]` `[Strings]` |
| KB324800 引文（5） | `[Unicode]` `[System Access]` **`[Kerberos Policy]`** `[Registry Values]` `[Version]` |

⚠️ **三份样本的段集合都不完全相同**，而且 `[Version]` 的位置也不固定
⇒ 解析器**不许**假设「一定有哪些段」「一定是什么顺序」。

`[Kerberos Policy]` 的键（来源 KB324800）：`MaxTicketAge` / `MaxRenewAge` /
`MaxServiceAge` / `MaxClockSkew` / `TicketValidateClient`。
本机两份样本里都没有它 ⇒ **列在白名单外，v1 只读**（改 `MaxClockSkew` 改错
= 全域认证失败）。

### 4.2 编码与行尾（E2 / E2b）

```
UTF-16LE + BOM(FF FE) + CRLF      ← GptTmpl.inf（三份样本一致）
```

**BOM 是承重的，不是风格偏好。** E2b 实测：同一内容去掉 BOM，编码探测落到
`cp1252`，于是整份文件解成「字符间夹 NUL」的乱码 ⇒ **段数 0**，而
**不抛任何异常**。

⇒ 设计约束：

* 写回时**原样保留** BOM（实现上用 `utf-16-le` 而不是 `utf-16`，
  把 BOM 当普通字符留住再吐回去，而不是让 codec 去猜端序）；
* **探测不到 BOM 时拒绝操作**（当作未知格式），**不许猜编码**。
  猜错一次的代价是把一份好策略写成垃圾，而下一次 `gpupdate` 才炸。

### 4.3 ⭐ `[Privilege Rights]` 的值有四种形态（E4）

这是本设计**最重要的一条**。实测：

```
secedit /export     星号SID 67 个 | 与号相对SID 0 个 | 域\账号 1 个 | 裸账号 3 个
     样例：  *S-1-5-32-544                     （星号 + SID）
            受限服务\所有受限服务                 （本地化的「域\账号」）
            Guest                                （裸账号，**无任何前缀**）

defltbase.inf       星号SID 65 个 | 与号相对SID 3 个 | 域\账号 0 个 | 裸账号 0 个
     样例：  &-501                              （与号 + 相对 SID）
```

**只认 `*SID` 的解析器，会静默漏掉 4/71 个主体。**

而 §1 已经说了 `[Privilege Rights]` 是**全量替换语义** —— 于是"漏认"和"删权限"
之间只隔一次保存：

```
读：SeInteractiveLogonRight = *S-1-5-32-544, Guest      ← 解析器只认出 1 个
界面：显示「Administrators」
使用者：看起来没问题，点了保存
写：SeInteractiveLogonRight = *S-1-5-32-544             ← Guest 被删了
```

这是本项目一直在猎的**「假成功」**形态：**提示成功、日志干净、界面对得上，
东西已经丢了。**

⇒ 设计约束：

* v1 里 `[Privilege Rights]` **只读**，但**显示必须把四种形态全认出来并标注类型**；
* 为 v2（如果要做）预先定下：**认不全就拒写**，不许「认得的保留、认不得的丢掉」；
* 判据必须**逐形态**有用例（`*SID` / `&SID` / `裸名` / `域\名` 各一条），
  **不许一条用例同时覆盖两种形态** —— 那种用例两条都证不了。

### 4.4 `[Registry Values]` 的类型码：表外的东西要"保留"不是"报错"（E5）

文件里**微软自己写着**这张表：

```
; REG_SZ (1)  REG_EXPAND_SZ (2)  REG_BINARY (3)  REG_DWORD (4)  REG_MULTI_SZ (7)
```

而 `defltbase.inf` 实测出现：

```
MACHINE\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters\NullSessionPipes=8,Remove:,lsarpc,samr,netlogon
```

**类型码 `8` + `Remove:` 前缀 —— 微软自己的注释表里没有它。**

⇒ 设计约束：遇到表外类型，**原样保留、只在界面上标注「不认识的类型，未修改」**。
**绝不**「报错删除」也**绝不**「按猜测的语义改」。

### 4.5 空值 ≠ 缺失

```
SeCreatePermanentPrivilege =            ← 键在，值为空 = 「没有人有这个权限」
（删掉这一行）                            ← 键不在 = 「这个设置不由本策略管」
```

两者语义**完全不同**。v1 的 `[System Access]` 里也有类似情形（
`NewAdministratorName` 被注释掉 = 不改名）。

⇒ 设计约束：**不许用「删行」来表达「清空」**；要清空必须写成空值 + 显式确认。

### 4.6 段名/键名大小写跨样本不一致（E3）

实测两种拼写**都真实存在**：

| 对象 | 拼写 A | 拼写 B |
|---|---|---|
| 段 | `[Version]`（secedit 导出） | `[version]`（自带模板） |
| 权限键 | `SeSystemTimePrivilege` | `SeSystemtimePrivilege` |

⇒ 匹配**全部** `re.IGNORECASE`。`str.find("[Version]")` 会在一半样本上失效，
而失效的表现是「找不到段」⇒ 如果又配了"找不到就跳过"，就是静默失效。

## 5. 红线（在需求 §1 六条之上，写操作特有的）

需求文档 §1 的六条**全部适用**（只增不减 / 改前快照 / 改后回读 /
不碰继承 / 身份显式 / 动手前探可达性）。在此基础上**再加四条**：

7. **定点行内替换**：解析结果**只用于展示**，写路径**不许**经过"重建文本"。
   实现上写成两个互不接触的函数：`read_*`（解析，给人看）与
   `patch_value`（字节定位替换，给机器写）。
8. **只改已存在的键的值**：不新增键、不新增段、不删键、不删段、不重排。
   「这个策略里没有这一项」要新增，是**另一个功能**（且属于危险的那一类）。
9. **前提不满足就本地拒绝，不发半个请求**：AD 属性（§6.3）、BOM（§4.2）、
   行尾（§4.2）、白名单（§1）任一不满足 ⇒ **在本地抛中文错误**。
   与需求 §1 第 6 条同一纪律。
10. **不许"认不全就丢掉"**：任何解析器遇到无法归类的行/值，
    一律**保留 + 标记**，绝不静默丢弃（§4.3 / §4.4）。

## 6. 改文件只是第一步：还要动 AD

### 6.1 双处版本号（E7）

改完 `GptTmpl.inf` 后**必须同时**递增两个地方，且**两者必须一致**：

| 位置 | 形式 | 怎么改 |
|---|---|---|
| SYSVOL 的 `GPT.INI` | `[General]` 段，`Version=65539` | **低 16 位 +1** |
| AD 里 GPC 对象 | 属性 `versionNumber`（32 位十进制整数） | **低 16 位 +1** |

编码规则（两个独立来源一致：MS Learn 的 GP 数据存储模块 + Scott 的 GP 博客）：

```
versionNumber = 高 16 位【用户配置版本】 : 低 16 位【计算机配置版本】
例：196615 = (3 × 65536) + 7  ->  用户 3 / 计算机 7
```

`GptTmpl.inf` 是 **MACHINE 侧**的设置 ⇒ 「只改了计算机版本」⇒
正确操作就是 `versionNumber + 1`（`GPT.INI` 同步 +1）。

**两者不一致的后果**：客户端认为策略没变 / DC 之间复制不到位，
表现为「GPMC 里看得到改动，客户机就是不生效」。

### 6.2 ⚠️ 微软 KB324800 给出的递增建议**是错的** —— 不许照抄

KB324800 原文：

> Increase the version number ... **Increment the number either by adding the
> number "0" to the end of the version number or the number "1" to the beginning.**

按位翻译一下（E7 实测输出）：

```
基线        65539   ->  用户 1  / 计算机 3
正确递增    65540   ->  用户 1  / 计算机 4     ← 只有计算机版本 +1
KB 的做法   655390  ->  用户 10 / 计算机 30    ← 用户版本凭空 +9、计算机版本凭空 +11
```

KB 那句话的目的是「让数字大到复制追不上」（它成文于 Windows 2000 时代、
手工改文件的语境），**它没有承诺语义正确**。照抄的后果是：**用户侧版本号也跳了**，
客户端可能对用户侧策略做一次无谓的重新处理，更糟的是这个数字从此失去意义，
以后排查「谁改了哪一侧」就无从下手。

⇒ 递增规则**自己按位算**，并且**判据要钉住这一点**（反证：把
`versionNumber + 1` 改成「字符串末尾加 0」，看用例是否变红）。

### 6.3 ⚠️ 还有第三个前提：`gPCMachineExtensionNames` 必须含安全 CSE GUID

来源：微软 **KB885009** + MS 论坛 addendum（Axel Limousin，含新建 GPO 的完整步骤）。

```
安全 CSE GUID: {827D319E-6EAC-11D2-A4EA-00C04F79F83A}
新建 GPO 时的完整取值: [{827D319E-...}{803E14A0-B4FB-11D0-A0D0-00A0C90F574B}]
```

**若该属性里没有这个 GUID，SYSVOL 里那份 `GptTmpl.inf` 会被完全忽略。**

这是最阴的一种失败：文件写对了、编码对了、版本号也涨了、GPMC 里甚至能看到，
但**策略就是不生效**，而**界面上没有任何线索指向"属性少了一个 GUID"**。

⇒ 设计约束（红线第 9 条的具体化）：

* **写之前先读** `gPCMachineExtensionNames`；
* 不含安全 CSE ⇒ **本地报中文错并拒绝写**（告诉使用者「这条 GPO 从来没有过
  安全设置，需要先在 GPMC 里手工加一项，或由工具的"启用安全扩展"功能补」）；
* 真域验证前，这一条**只能算"文档已确认、本机未实测"**（见 §10）。

## 7. 接口设计

新模块 `gpo_security_backend.py`，与 `gpo_backend.py`（COM）/
`ad_client.py`（LDAP）平级。**零 UI**。

```python
# ---------- 数据 ----------
@dataclass(frozen=True)
class InfLine:
    """一行原始文本 + 它的解析结果。**原文必须留着** —— 写路径要用它定位。"""
    index: int
    raw: str                      # 原样（含缩进）
    kind: str                     # "section" | "entry" | "comment" | "blank"
    section: str = ""
    key: str = ""
    value: str = ""
    principal_kind: str = ""      # 仅 [Privilege Rights]：星号SID/与号相对SID/裸账号/域\账号
    known: bool = True            # False = 认不出来 ⇒ 界面标「未修改」，写路径跳过

@dataclass(frozen=True)
class SecurityTemplate:
    path: str                     # 真实 UNC，来自 GPC 的 gPCFileSysPath（禁硬编码）
    codec: str                    # "utf-16-le"
    has_bom: bool
    line_ending: str              # "crlf"（其它一律拒写）
    lines: tuple[InfLine, ...]
    md5: str                      # 快照用
    raw: bytes                    # 快照用（原字节）
    writable_keys: frozenset      # 白名单，见 §1

# ---------- 读（纯函数，无副作用，可离线测）----------
def parse_template(raw: bytes) -> SecurityTemplate
    """解析。**遇到认不出来的东西不许丢**，标 known=False 留着。

    ⚠️ 段名/键名一律 re.IGNORECASE（E3 实测两种拼写都存在）。
    """

def decode_version(v: int) -> tuple[int, int]      # (用户, 计算机)
def encode_version(user: int, computer: int) -> int

def bump_computer_version(v: int) -> int
    """低 16 位 +1。**不许**用「字符串末尾加 0」那种做法（§6.2）。"""

# ---------- 写（字节级，最小内核）----------
def patch_value(raw: bytes, section: str, key: str, new_value: str) -> bytes
    """定点行内替换。**唯一**的写入口（红线第 7 条：写路径不经过重建）。

    ⚠️ 找不到键 / 段不存在 / 键出现多次 / 行尾非 CRLF / 无 BOM ⇒ **抛异常**。
    **不许**"没找到就跳过"。E6b 已把这四种情形固化成实验。
    """

# ---------- 会话（真机）----------
@contextmanager
def open_target(domain: str, gpo_guid: str, *, dc: str = "", user="", password=""):
    """打开一条 GPO 的安全模板。

    * `gPCFileSysPath` 从 LDAP 读（**禁硬编码**）；
    * 写 SMB 用**显式凭据**（`WNetAddConnection2`）；
      LDAP 改属性也用显式绑定（`ntlm_bind_identity`）。
      ⇒ 两条路都自带凭据，**因此不需要 `impersonate`**，
        也就绕开了 `impersonate` 那条"退出顺序"的坑（详见 gpo_backend 的设计注记）。
        ⚠️ 这一点**未在真域验证**（§10）。
    """

def write_changes(handle, changes: dict, *, apply: bool) -> WriteResult
    """`apply=False` 只做**预检**（dry-run），不写任何东西。

    顺序（§6）：
      1. 快照：文件原字节 + md5 + AD 侧 (versionNumber, gPCMachineExtensionNames)
      2. 预检：BOM / 行尾 / 白名单 / CSE GUID / 可达性 —— 任一不过就在这里抛
      3. 写 SYSVOL 文件（定点替换，可能多处）
      4. 改 AD：versionNumber +1（CSE 缺失时**不在这一步补**，因为那是"启用安全扩展"，
         属于另一个功能，见 §11）
      5. 回读校验：**字节差异必须恰好是预期的几处**，且 AD/文件两处版本号一致
      6. 任一步失败 ⇒ 回滚（文件写回快照字节 + AD 写回快照值），
         并把快照落到审计里，让使用者能手工恢复
    """
```

**为什么 `patch_value` 单独拿出来、且签名是 `bytes -> bytes`**：
它是一个**纯函数**，可以在没有域、没有 SYSVOL、没有权限的机器上把
E6/E6b 那套实验跑成**单元测试**。把"最难验的东西"变成"最容易验的东西"
是本项目反复用过的手法（`probe_acl_write_semantics` 同理）。
