# 帮帮AD域管理工具 · bbad

> 一个**没加域也能用**的 Active Directory 轻量管理工具，覆盖 ADUC（`dsa.msc`）的常用部分：
> **解锁 / 启用禁用 / 重置密码 / 新建用户 · OU · 组 / 属性编辑 / 组策略只读查看**。
> Python + PyQt6 单机桌面程序，产物 `bbad.exe`。

---

## 为什么需要它

`dsa.msc` 连域控时要先做 DNS 校验。在**没有加入域**的机器上，它经常直接报
「指定的域不存在，或无法联系」——哪怕网络是通的、账号密码是对的。

本工具绕开这一步：

* 走 `ldap3 + NTLM`（身份用 `域\用户` 形态，不用 UPN）**直连 IP**；
* 连之前先匿名读 `RootDSE` **反查域名与 BaseDN**；
* 于是判据变成一句话：**只要 389 通、账号密码对，就能管**。

改密是双通道降级：先走 **RPC**（`WinNT://` + `LogonUser` 模拟，135/445），
失败再走 **LDAPS**（`modify_password`，636）。
认证类 / 策略类错误**不降级** —— 否则一次「密码不符合策略」会被糊成"所有通道都失败"。

## 安全与审计

| 项 | 做法 |
|---|---|
| 明文密码 | **不落盘**。勾了「记住密码」才会用 Windows **DPAPI** 加密存起来（作用域 = 本机 + 本账号，拷走也解不开） |
| 审计日志 | 所有修改类操作都记本地审计，含**操作前 / 操作后**的值 |
| 密码 | 审计里**永不出现**密码明文 |
| 配置位置 | `%APPDATA%\AD域管理工具\`（**不在 exe 同目录** —— exe 常在 U 盘/共享盘，写权限不稳） |
| 脱敏 | 仓库里有一道**机制式守卫**（`tests/test_no_real_env.py`）钉住"生产模块不许出现真实环境字样"：IPv4 按 **RFC 5737** 文档地址白名单判定，`DC=` 串与 `域\用户` 身份按 **RFC 2606/6761** 保留域名判定，另加一份**每个词都写明理由**的禁区名单 |

> 内置**演示模式**：所有数据都是假的（文档段地址 + `demo.local`），任何操作都不影响真实域。
> 仓库里的截图全部出自演示模式。

## 快速开始

### 跑源码（开发期，1~2 秒反馈）

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
run_dev.bat
```

### 出 exe

```bat
build.bat            :: onedir（默认，启动 1 秒内）
build.bat onefile    :: 单文件（发网盘用，启动慢 3~6 秒）
```

产物：`dist\bbad\bbad.exe` / `dist\bbad.exe`

> `build.bat` 带 5 道自检：虚拟环境 → 依赖能否导入 → PyInstaller → 语法 → **产物是否真的存在**
> （PyInstaller 偶发"退出码 0 但没产物"，所以不许只看退出码）。
> 打完还**必须**把产物拷到一台**没装 Python 的**机器上双击 —— 自己这台跑得起来不算证据。

## 目录

```
<生产模块 .py>          30 个：程序本体（ad_client / ui_* / config / audit / password_backend …）
docs/                  设计、事故复盘、对标 ADUC 的差异清单
screenshots/           界面截图（**全部出自演示模式**，UI 里的地址/账号都是占位值）
bbad.spec              打包规格（显式点名了 win32timezone / pythoncom / Crypto.Hash.MD4
                       这些**运行期懒加载**的模块 —— 漏了会在"改密"那一步才炸）
build.bat / run_dev.bat
requirements.txt
```

> ⚠️ **本仓库不含 `tests/` 与 `tools/`。**
> 那两部分是本项目的质量装置（单元 + 行为测试、反证框架、验收脚本、根因探针），
> 但它们**按设计就要拿真实环境现身说法**：脱敏守卫的禁区词表里，那条"真实账号名"的
> 理由原文写得很直白 —— 「**供验收脚本现身说法，不许进生产模块**」。
> 也就是说：**生产模块干净，证据件带真值**，这是有意为之。
> 本地自用没问题；公开出去前提就变了 ⇒ 本仓库把这两块留在本地。
> **`docs/` 是例外**：它是文案，已按 **RFC 5737 / RFC 2606** 把里面的真实地址与账号
> 换成保留值（`192.0.2.x` / `*.example.com`），所以可以公开。

### 分层纪律（本项目的核心约束）

```
ad_client 以下  ── 零 UI：不 import 任何 PyQt
ui_*           ── 零 LDAP / 零 COM：只发指令、收结果
模型更新        ── 只在主线程
异步回调        ── 绑定"发起时归属"，禁止读"面板现在显示谁"
```

## 测试

本仓库不含测试；本地保留部分的跑法：

```bat
.venv\Scripts\python -m unittest discover -s tests -t .
```

> 反证脚本会**原地改源码**再验证"该红的一定红"，所以**跑测试套件时不要同时跑反证脚本**
> （会互相干扰，产生 phantom 红）。

## 数据与隐私

* 本仓库**不含**任何真实域控地址、账号或口令；
* 程序运行期产生的连接配置、审计日志、运行日志**全部落在 `%APPDATA%`**，
  且已被 `.gitignore` 显式挡住（防呆）；
* 换一台机器运行 = 全新的空配置，需要自己填域控信息。
